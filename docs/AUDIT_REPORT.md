## 1) خلاصة تنفيذية

الأساس الأمني قوي أصلاً: رموز opaque مخزّنة كـ SHA-256، كلمات مرور scrypt، OTP مجزّأ بمفتاح، تحديد معدّل لكل مسار وللحسابات، عزل المنظمات (`organization_id` إلزامي) وعزل المشاريع (404 لغير الأعضاء)، فصل المهام في اعتماد الطلبات، والـ BFF يُبقي الرمز في كوكي HttpOnly. التدقيق وجد **فجوات محددة** (لا مشاكل معمارية)، أهمها:

| # | الفجوة | الخطورة | الحالة |
|---|---|---|---|
| 1 | لا يوجد تغيير كلمة مرور للمستخدم المسجَّل (فقط "نسيت كلمة المرور") | متوسط | ✅ نُفِّذ |
| 2 | قرارات المشغّل (اعتماد/رفض/تعليق منظمة) بلا أثر في `audit_logs` | متوسط | ✅ نُفِّذ |
| 3 | الـ BFF لا يتحقق من `Origin`/`Sec-Fetch-Site` للطلبات المغيِّرة (الاعتماد على SameSite=lax فقط) | متوسط | ✅ نُفِّذ |
| 4 | لا ترويسات أمان في Next (nosniff، frame، HSTS…) | تحسين | ✅ نُفِّذ (بدون CSP) |
| 5 | CI يشغّل lint+build للواجهة فقط؛ **اختبارات الـ backend (~499) والواجهة لا تُشغَّل في CI**، ولا يوجد اختبار على PostgreSQL | حرج (تشغيلي) | ✅ نُفِّذ |
| 6 | Node 20 في CI بينما الـ backend يشترط `>=22` | متوسط | ✅ نُفِّذ |
| 7 | تعليقات قديمة تذكر Laravel (تضليل للمطوّرين) | تحسين | ✅ نُفِّذ |
| 8 | محدِّد المعدّل في الذاكرة لكل عملية (لا يُشارَك بين نسخ متعددة) | متوسط | ⏳ مرحلة 2 |
| 9 | لا يوجد حذف ملف (`DELETE /files/:id`) ولا واجهة له | تحسين | ⏳ مرحلة 2 |
| 10 | لا CSP (يحتاج nonce لكل طلب مع Next) | تحسين | ⏳ مرحلة 2 |
| 11 | `audit_logs` لا تغطي بعد: الطلبات/المهام/الملفات/الأدوار (ما عدا تغيير دور موظف) | تحسين | ⏳ مرحلة 2 (`writeAudit` جاهز) |
| 12 | لا اختبارات E2E في CI (Playwright موجود محلياً) | تحسين | ⏳ مرحلة 2 |

### ج) الصلاحيات والعزل (RBAC / tenant / project)
مراجَع بالكود، **لم أجد ثغرة عزل**: كل جدول يحمل `organization_id` (NOT NULL)، `project_id` إلزامي (migrations 11/12)، `assertProjectAccess` يُرجع 404 لغير الأعضاء، 23 مفتاح صلاحية تُفرض في الـ backend عبر `app.guard`، والواجهة تخفي فقط (عرض وليس تحكّم). فصل المهام: لا يعتمد صاحب الطلب طلبه.
نقطة انتباه (ليست ثغرة): أي مسار جديد يجب أن يمر عبر `app.guard` — الاختبارات الحالية تغطي ذلك للمسارات القائمة.

## 3) مصفوفة الدور ↔ العملية

الرموز: ✅ مسموح · ⛔ محجوب · ◐ مشروط. "المنظمة المعتمدة" = `organizations.status = approved`.

| العملية | زائر | مسجَّل جديد (منظمة غير معتمدة) | مدير المنظمة (system admin) | موظف/عضو (حسب الصلاحيات) | مشغّل المنصة | فريق المشروع |
|---|---|---|---|---|---|---|
| التسجيل / تأكيد البريد / نسيت كلمة المرور | ✅ (محدود المعدّل) | — | — | — | — | — |
| الدخول | ✅ | ✅ (يرى مسار التهيئة فقط) | ✅ | ✅ | ✅ | ✅ |
| **تغيير كلمة مروري** | ⛔ 401 | ✅ | ✅ | ✅ | ✅ | ✅ |
| أعمال المنظمة (طلبات، مهام، ملفات…) | ⛔ | ⛔ 403 حتى الاعتماد | ✅ | ◐ حسب مفاتيح الصلاحية | ⛔ (لا ينتمي لمنظمة) | ◐ + عضوية المشروع |
| إدارة الأدوار/الموظفين/القوائم | ⛔ | ⛔ | ✅ | ◐ (`roles.manage`، `employees.*`، `settings.manage`) | ⛔ | ⛔ |
| اعتماد/رفض/تعليق منظمة | ⛔ | ⛔ (لا يعتمد نفسه) | ⛔ | ⛔ | ✅ (+ سجل تدقيق) | ⛔ |
| الوصول لمشروع | ⛔ | ⛔ | ◐ عضو فقط (404 لغير الأعضاء) | ◐ عضو فقط | ⛔ | ✅ حسب دور المشروع (admin/supervisor/member) |
| اعتماد طلب | ⛔ | ⛔ | ◐ ليس صاحب الطلب | ◐ بالصلاحية وليس صاحبه | ⛔ | ◐ |

التعارضات التي فُحصت: الواجهة تخفي العناصر حسب `permissions` لكن الحسم دائماً في الـ backend (`can()` + `guard`)؛ لا تعارض ظاهر. عند غياب قائمة الصلاحيات في الجلسة تُظهر الواجهة العناصر (لا تمنح شيئاً).

## 4) الخطة المرحلية

**المرحلة 1 (نُفِّذت على هذا الفرع):** تغيير كلمة المرور (backend + واجهة + اختبارات)، تدقيق قرارات المشغّل، حماية CSRF في الـ BFF، ترويسات الأمان، تصحيح CI والـ Node، تنظيف التعليقات.

**المرحلة 2 (مقترحة):**
1. تشغيل الحزمة كاملة وإصلاح ما قد يظهر (§6).
2. توسيع `writeAudit` إلى: الطلبات (إنشاء/اعتماد/رفض)، المهام، الملفات، الأدوار، تغيير عضوية المشروع + شاشة عرض للمدير.
3. `DELETE /files/:id` (صلاحية `files.delete` أو `files.upload`+مالك، تدقيق، حذف الملف من القرص، زر في الواجهة وتأكيد).
4. محدِّد معدّل مشترك إذا تعددت النسخ.
5. CSP بـ nonce، وربط Playwright E2E في CI.

## 6) طريقة التحقق

```bash
# Backend (SQLite)
cd backend && npm ci && npm test
npx vitest run test/change-password.test.js          # الاختبارات الجديدة فقط
# Backend على PostgreSQL
TEST_DATABASE_URL=postgres://user:pass@localhost:5432/postgres npm test
# Frontend
cd ../frontend && npm ci && npm run lint && npm test && npm run build
```

تحقق يدوي:
1. سجّل الدخول من متصفحين، غيّر كلمة المرور من **حسابي** في الأول → الثاني يُطرد (401) والأول يبقى.
2. كلمة حالية خاطئة 5 مرات → 429 لمدة 15 دقيقة.
3. اعتمد/ارفض منظمة من لوحة المشغّل ثم: `select action, actor_id, meta from audit_logs order by id desc;`
4. `curl -i -X POST -H "Origin: https://evil.example" http://localhost:3000/api/auth/logout` → 403.
5. `curl -I http://localhost:3000/` → ترويسات الأمان ظاهرة.

**احتمالات فشل متوقعة عند أول تشغيل** (لأنني لم أستطع التشغيل): اختبار الواجهة قد يحتاج تعديل استعلامات النص (`getByLabelText`) إن اختلف ترتيب التسميات؛ وقد يطلب lint ترتيباً معيّناً للاستيراد. أصلحها فور ظهورها — لا تغيّر منطقاً.
