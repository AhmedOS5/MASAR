# رحلات المستخدمين حسب الدور (User Journeys)

مكتوبة لفريق المشروع ولجنة التقييم. لكل رحلة: الخطوات، الشاشة/المسار، الصلاحية المطلوبة، وهل الخطوة **قابلة للوصول من الواجهة اليوم**.
حسابات التجربة في [demo-accounts.md](./demo-accounts.md). المرجع التقني: [api-contracts.md](./api-contracts.md).

**رموز الحالة:** ✅ متاحة في الواجهة · ⚠ ناقصة أو مضلِّلة (انظر الفجوات) · ⛔ خارج الواجهة (CLI أو API فقط).

> **كيف تم التحقق:** بقراءة الصفحات والخدمات (`frontend/src/services/*`) والمسارات والصلاحيات في الـ backend، ومطابقتها مع اختبارات
> الـ e2e الموجودة (تسجيل منظمة، دعوة موظف، المشغّل، الطلبات، المهام، MEAL). **لم** تُجرَّب كل رحلة يدوياً في المتصفح بكل دور؛
> الخطوات المعلَّمة ✅ بلا اختبار e2e مباشر مبنية على قراءة الكود فقط.

## المسميات الوظيفية الثابتة وحِزم الصلاحيات (أربع فئات فقط)
المنظمة لا تخترع مسمىً وظيفياً بصلاحيات جديدة: كل موظف ينتمي إلى إحدى أربع فئات، وتأتي معه **حزمة صلاحيات** مقسومة إلى **اطلاع** و**تعديل**.
تُعيَّن الحزمة تلقائياً عند إضافة الموظف (بالفئة أو بالمسمى)، ويستطيع مدير النظام تجاوزها يدوياً مع تسجيل ذلك. التفاصيل في [api-contracts.md §8b](./api-contracts.md).

| الفئة | الدور | اطلاع | تعديل |
|---|---|---|---|
| `manager` مدير / مشرف مشاريع | مدير | الطلبات، المهام، الموظفون، الأدوار، الملفات، التقارير، الوحدات، MEAL، المشاريع، المستفيدون | إنشاء الطلبات والموافقة عليها، إنشاء المهام وتعديلها، رفع الملفات، إدارة التقارير، تعديل بيانات المستفيدين |
| `meal` متابعة وتقييم / ميداني | مسؤول متابعة وتقييم | الطلبات، المهام، الملفات، التقارير، الوحدات، MEAL، المشاريع، المستفيدون | إنشاء الطلبات والمهام، رفع الملفات والصور، إدارة التقارير، إدارة MEAL، تسجيل المستفيدين وتعديلهم |
| `finance` مالية | مسؤول مالي | الطلبات، المهام، الملفات، التقارير، الوحدات، المشاريع (**بلا** بيانات المستفيدين) | إنشاء الطلبات والموافقة عليها، رفع الملفات، إدارة التقارير |
| `employee` موظف | موظف | الطلبات، المهام، الملفات، التقارير، الوحدات، المشاريع | إنشاء الطلبات، رفع الملفات والصور |

مدير النظام (`is_system_admin`) يملك كل الصلاحيات ولا يُعيَّن تلقائياً أبداً. لا حزمة تملك إدارة الأدوار أو الموظفين أو الوحدات أو الإعدادات أو إنشاء المشاريع:
هذه لمدير النظام وحده. **الحزمة تقول ماذا يفعل الشخص، وعضوية المشروع تقول أين:** لا يرى المشروع ولا طلباته ومهامه ومستفيديه وملفاته إلا فريقه.
كل مستخدم يرى في القائمة الجانبية وفي الأزرار ما تسمح به حزمته فقط.
